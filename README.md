# OpenWrt 24.10 для TL-WR840N v4: USB + дві USB-вебкамери + меню «Вебкамери» (v5, оптимізована)

## Що нового у v5
- **Патч 040** (mjpg-streamer): при `select() timeout` або помилці захоплення стрім перезапускається на місці (до 3 спроб).
  Якщо не вдається, процес одразу завершується, і procd піднімає чистий екземпляр (`respawn 3600 5 0`: 5 с затримки, без ліміту спроб).
  Раніше вхід помирав, звільняв буфер, поки HTTP-вихід ще його читав, і виникав SIGSEGV.
- **Патч 050** (mjpg-streamer): YUYV -> JPEG напряму з YCbCr 4:2:0 (`raw_data_in`) + `JDCT_IFAST`, без пікселя-за-пікселем YUV->RGB.
  Бенчмарк без SIMD (як на MIPS): у 1.5-2.4 раза швидше, PSNR не гірший (352x288 q80: 2.83 -> 1.16 мс/кадр; 640x480: 6.7 -> 3.9 мс).
- За замовчуванням збирається `openwrt-24.10`.

## Збірка
1. Залийте вміст папки в репозиторій GitHub (разом з `.github/`).
2. Actions -> Build OpenWrt TL-WR840N v4 -> Run workflow, поле: `openwrt-24.10`.
3. Artifacts: `sysupgrade.bin`, `tftp-recovery.bin`, `SHA256SUMS`, `config.used`.
   У лозі останнього кроку видно розмір `sysupgrade` відносно ліміту 7808 КБ.
4. Крок «Patch mjpg-streamer» кладе патчі з `patches/mjpg-streamer/` у feed; якщо вони не лягають, збірка падає (пришліть лог).

## Рекомендації після прошивки
- Починайте з 352x288 @ 5 fps або 320x240 @ 10 fps, потім піднімайте по одному параметру й дивіться `top`.
- У логах `logread | grep mjpg` рядки `select() timeout` + `exiting for respawn` означають автоперезапуск.
